# 实现约定

状态流程：进入拍摄页 → PREVIEW（单麦克风测量/定位，不持久化）→ 点击录像新建累计引擎 → EVIDENCE（单段录像）→ FINALIZING → 正常结束返回新PREVIEW，异常/离页/后台返回IDLE。CALIBRATION单独使用原始数字电平。

0.1.4新增媒体每个独立归属一个EvidenceSession，旧多媒体记录不拆分。Camera2与EGL由单个工作线程持有；AudioRecord单独线程将同一份PCM交给计权引擎和AAC编码。视频不再次开启麦克风。统计引擎以样本数量/单调时钟计时；相机时间源REALTIME直接对应elapsedRealtime，未知源采用最小已观测投递偏移并保障递增，避免首次画面排队造成后续时间持续偏向未来。相机帧选择不晚于该帧的测量/位置快照。

EGL合成相机纹理与Canvas水印面板至一个FBO。相机SurfaceTexture可能已经包含传感器旋转，只补充所需差角，避免重复旋转。预览与H.264取同一FBO，JPEG从FBO读回并翻转行序。水印最多4Hz重新绘制/上传，横屏与竖屏有各自布局。

录像：建立编码器 → 接入Surface → 收取共享PCM → 等待两轨格式 → 启动muxer → 编码写入 → 停止接入PCM与视频 → 双轨EOS → muxer.stop/release → `.part`更名 → 标记完成并计算哈希。错误路径不把未完成录像标为成功。

视频帧最多领先已接收的有效PCM末端50ms；未接收PCM时不编码画面，防止输入中断后持续出现无声尾段。封装时显式设置视频轨EOS时刻，避免MediaMuxer使用此前丢帧间隔推算最后一帧时长。音频逻辑采样末端落后投递时刻超过1秒或超前超过250ms时终止采集并记录错误。这些保护不能代替真机视听脉冲同步验收。

Room会话使用Upsert保持父记录，避免REPLACE触发外键级联删除媒体。文件在应用私有目录，分享使用FileProvider临时读权限。会话每5秒checkpoint，完成时生成metadata；启动时将未结束会话标记中断。

会话建立时保存的应用版本、设备、起始时区、坐标体系与滤波配置在后续完成/导出时保持原值。系统时间或时区变化另记事件，媒体时间不回填；逐秒CSV用同一单调/墙钟参考对映射采样时间。

Activity停止时触发取证结束。收尾使用独立于ViewModel清理的作用域，普通退出等待录像及在途照片提交后释放采集。系统强杀不承诺最后未封装MP4可恢复。

校准绑定输入配置；输入路由改变中断本次取证。位置不依赖GMS/地图SDK，无位置权限仍可记录，但水印显示未定位。新记录不查询地名，不修改既有媒体。

JSON/CSV使用UTF-8。历史格式版本1单位由calibrated决定；新格式版本2由LevelReference明确DIGITAL/ANDROID_NOMINAL/USER_REFERENCE、偏移和依据。校准替换标称偏移；统计仅加一次偏移，显示格式不修改存储值。Room版本1→2仅添加nullable levelReferenceJson/galleryUri，历史数据与媒体不重新换算。


## 0.1.2 审查后的补充约定

- 结束取证先停止音频/位置并固定采集结束时刻，再完成编码、文件哈希和持久化。收尾耗时不计入取证时长。`MeasurementEngine.finish` 将结束边界前缺失的完整秒标为无效，保留不足一秒的有效采样统计。
- 文件/数据库提交、元数据、导出和删除由同一存储互斥锁保护。大媒体的 SHA-256 在锁外计算，该媒体保持「写入中」，所以同次取证的逐秒落盘不会被哈希计算阻塞；导出和删除拒绝待提交媒体。
- 导出仅允许固定数据文件、已提交且哈希匹配的媒体、已有损坏日志备份。导出不清理失败文件。ZIP 先写 `.part` 再更名，并发导出串行处理。
- 启动恢复分别处理每条记录。JSONL/CSV 仅修复缺少换行且解析不完整的最后一行，中间损坏明确报错。原始备份仅首次建立；修复内容写临时文件、同步后更名，失败时保留原日志和备份。恢复结束时间来自最后持久化的采集边界。
- 定位状态只在主线程修改，拒绝过期顺序、非法坐标和未来时间。地名回调须同时匹配会话代次和原定位点，停止或开始新记录后旧查询不能更新界面或文件。
- AudioRecord 在创建后立即取得清理所有权；EGL 构造失败和上下文失效时尽力释放所有已创建资源，重复关闭安全。持久化失败也会清空活动会话、忙碌状态并关闭采集。
- 横竖屏共用一个预览组件。SurfaceView 重建期间允许重新连接预览；进入后台仍由 Activity 的生命周期结束取证。照片拒绝超过250毫秒的旧相机画面。

## 0.1.3 相册保存与并发

MediaStore Images/Video写入DCIM/DecibelEvi，IS_PENDING=1时原样复制并校验SHA-256，发布后提交URI。AtomicFile日志跟踪本应用创建的待完成URI，启动恢复清理未发布项或补交已发布URI；不扫描删除其他相册内容。复制出错/取消会清理半成品。仍存在的已发布URI重复保存时跳过；相册副本独立于内部记录删除。

保存相册持有仓库存储锁，避免内部删除与复制竞态。ViewModel在主线程设置保存状态，取证启动/相册保存双向拒绝重叠，避免大文件复制阻塞逐秒持久化而丢失60秒窗口之外的数据；预览不写仓库，可继续运行。

## 0.1.4 独立拍摄、名称和内置查看

单AudioRecord的PCM同时驱动视频累计引擎和连续照片窗口引擎，视频仍使用相同PCM编码。窗口在录像边界保留、离页清空。照片取不晚于相机帧的有效快照（250ms内），冻结60秒内完整秒的声能平均和Fast最大；JPEG与该快照共用合成。照片生成独立零时长记录，CSV原点单独写入photoMeasurement并在后续导出/改名时保留。录像中拍照不改变活动录像会话。

Room v3增加nullable displayName（2→3增列，支持1→2→3），空白存null。仓库改名保留原metadata未知字段、捕获字段和所有媒体；UI空名称回退捕获日期时间。原始文件名与媒体哈希不变。

MediaViewer使用全屏Dialog、采样Bitmap解码、VideoView/MediaController，不新增播放器依赖。图片解码在IO线程，取消时回收未发布位图，已发布位图由GC回收；视频后台暂停、关闭stopPlayback。
